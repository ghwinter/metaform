# 06 AI 原生假设：把"人"从成本模型里去掉

原设定沿用了 FCA 属性探索的姿势：人给属性、人答成员问题。这套系统是给 LLM/AI 用的，
那个假设必须换掉。换掉之后有些结论变强，有些要重新表述。

## 1 三条替换

| 旧假设 | 新假设 | 后果 |
|---|---|---|
| oracle 是人，答一次很贵 | oracle 是程序 / 测试 / Lean / 模型本身，**回答便宜且可并行** | 提问不再是稀缺资源，**提议才是** |
| 一次一问、一问一答 | 模型一次调用可以答几百个成员问题 | 成本单位从"一次查询"变成"**一轮（batch）**" |
| 使用者是人，看概念格 | 使用者是 agent，读结构化状态 | 接口要给 JSON，不是给人看的表格 |

## 2 哪些结论不变

- **T2 / T6 / T7 完全不变**：它们只谈词汇与签名，与谁回答无关。
  撞车了就是撞车了，无论 oracle 是人还是编译器。
- 论文的判据因此更硬：它不依赖"专家愿意配合"这个社会学前提。

## 3 哪些要改

**T5 的下界要按轮算。** 若一轮能问 k 个对象、每轮成本 1，则识别 |F| 个候选仍需
`k · rounds ≥ log2 |F|` 比特，但 **rounds ≥ ⌈log2|F| / k⌉**。
工程含义：与其设计"下一个问谁"，不如设计"**这一轮问哪 k 个**"——一轮问满每个未决类的代表，
是最优的批量策略（域 A 已证：类内选谁无所谓）。

**成本模型翻转。** 设一次提议成本 `r`（生成 + 校验），一轮批量查询成本 `c`，命中率 `q`。
总成本 `≈ (r/q) + c·rounds`。域 A/成本实验里 `r/q` 主导（44× 跨度，停止规则只差 ±6%）——
在 AI 设定下这个结论只会更强，因为 `c` 比 `r` 更小。

**自我裁决必须禁止。** 若 oracle 与提议者都是同一个模型，答案与提议共享同一个错误来源
（TACL 2024 综述：没有证据表明仅靠提示反馈能自我纠错）。所以流程要求：可判定的部分交给
程序（测试、Lean、执行），不可判定的部分交给**另一个**模型或人。

## 4 对引擎接口的要求

agent 不该读表格，应该读 JSON。`qde need` 应输出：

```json
{
  "status": "INSUFFICIENT",
  "classes": 2,
  "free_classes": 0,
  "colliding_pairs": [[0,4],[0,5],[1,4],[1,5]],
  "suggested_labels": []
}
```

以及 `qde batch k`：给出这一轮该标注的 k 个对象（每个未决类一个代表），一次问完。

agent 拿到 `colliding_pairs` 之后要做的事很明确：**生成能劈开这些对的谓词**，
而不是"再多想想"。这就是 T7 的接口化。

## 5 对我自己（这个 agent）意味着什么

我不是这套系统的操作员，我是它的用户之一。可用的姿势：

1. 分析代码库时：对象=案例/函数，谓词=可执行特征，撞车对=行为相同但结论不同的两个案例。
   `need` 直接告诉我"这两个案例在任何现有特征下都一样，必须换一个特征"。
2. 读论文时：对象=论文，谓词=方法特征，撞车对=看起来不同但判断相同的两篇——
   这恰好是我做文献综合时最容易错的地方。
3. 做实验时：对象=配置，谓词=指标阈值，撞车对=指标相同但结果不同的配置。

这三件事我都做过，且都是靠感觉做的。引擎的价值是把"靠感觉"换成"状态机说不够，就换特征"。

## 6 一条克制

不要把"AI 用"当成"可以无限调用"。提议成本 r 在真实系统里是长上下文 + 校验，
一轮几百个成员查询也不是免费。**成本模型要保留，只是换成 token / 调用次数**。
没有成本，就没有"该不该扩词表"的问题，整篇论文就退化成"多试几个特征"。

## 7 oracle 的返回值要带票数

模型当 oracle 会错，而且错得不独立。合成实验（`RESULTS.md` §3.10）给出的量化：

| 每次回答错误率 ε | r=1 假触发 / 漏检 | r=5 假触发 / 漏检 |
|---|---|---|
| 0.05 | 4.0% / 0.0% | 0.0% / 0.0% |
| 0.10 | 10.0% / 1.7% | 0.5% / 0.0% |
| 0.20 | 9.0% / 18.6% | 0.5% / 0.0% |
| 0.30 | 12.0% / 20.5% | 8.0% / 8.2% |

因此 `Oracle::ask` 不该返回 `Option<bool>`，应该返回 `(yes: u8, no: u8)` 或一个校准过的
置信度；**关键判定（决定要不要换词表的那一次）必须重复问**，非关键判定可以只问一次。

这条也解释了为什么"再问一遍"在 AI 设定下不昂贵——它比提议便宜，而且能把假触发率压一个数量级。

**已实现**（`engine/src/lib.rs`）：`Explorer::answer_votes(x, yes, no)` + `status_with(theta)`，
`theta` 是"确证"所需的票差；`theta` 大了，噪声票不再被当成撞车，状态退回 `Undetermined` 而不是误报。

```
$ qde vote 0 5 1      # obj 0 五票是、一票否
$ qde need 6          # 要求票差 ≥ 6 才确证
{"status":"UNDETERMINED","action":"ASK","theta":6,...,"colliding_pairs":[],...}
```

同一条数据在 `theta=1` 下会报 `INSUFFICIENT`，`theta=6` 下不会——噪声门就是这么工作的。

**默认 θ=3**，依据是完整循环实验（`RESULTS.md` §3.11）：

| ε | θ=1 | θ=3 | θ=5 |
|---|---|---|---|
| 0.1 | 0.25 | **0.98** | 1.00 |
| 0.2 | 0.07 | 0.83 | **0.99** |
| 轮数（ε=0.1） | 5.7 | 15.6 | 22.1 |

经验规则 `θ ≈ 2 + 10ε`：ε≤0.1 用 3，ε≈0.2 用 4–5。θ=1 在噪声下会提前认定并交出错误外延，
这是数量级的差别，不是收尾问题。

**自适应 θ 试过，被否决**（`RESULTS.md` §3.12）：在 ε=0.1 时它多花 44% 轮数只换来 0.01 的
成功率提升，在 ε=0.2 时省 11% 轮数但成功率 0.94 < 1.00。两个固定值把自适应夹在中间，
所以改成"估 ε → 直接选 θ"，不做在线调节。

估 ε 的办法很便宜：投票里少数票的比例就是 ε 的直接估计（`min(yes,no)/(yes+no)` 的均值）。
**已实现**：`Explorer::implied_epsilon()` 与 `recommended_theta()`（≤0.1→3，≥0.2→5，中间 4），
`qde need` 直接输出 `epsilon_hat` 与 `theta_rec`。

**验证**（`RESULTS.md` §3.13）：ε≤0.2 时用估计值选 θ 与用真实值差 ≤1 个百分点，ε=0.2 时还便宜
15% 轮数；ε=0.3 时差到 7 个点。所以这套自校准的适用范围是 **ε ≤ 0.2**，再高就得换逐对象后验，
不能靠调阈值。

**但逐对象后验也失败了**（§3.14）：δ=0.05 的 Beta 门在每一档都比 θ=5 慢，ε=0.3 时还更差。
原因是加票本身也暴露在噪声里——轮数越长，被翻盘的机会越多。**噪声这条线到此为止**：
再往上要走"问得更好"或"给噪声建模"，不是继续调阈值。
